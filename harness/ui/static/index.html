    Welcome to dev-loop

    Two clicks and this repo is wired up.

      What this does
      • Writes .dev-loop/config.yaml with sane defaults.
      • Adds .dev-loop/runs/ to .gitignore.
      • Installs a tiny hello-dev-loop replay scenario so you can hit "Try the demo run" and watch a full pass-through.

      Flow overview

      The orchestration is built from five pieces. Click any to edit.

      1. Task contract — agent restates the request as goal + success criteria.
        schema · playbook
      2. Implementation in disposable sandbox.
        playbook · schema
      3. Patch extraction & clean reapply.
      4. Validation through registered capabilities (Jenkins, deploy, E2E).
        capabilities
      5. Triage on failure → next action (modify code, ask more diagnostics, escalate).
        schema · playbook

      Loop policy, scenarios and runs dir live in config.

      Repository config

      Provider & paths

      Which agent runs when --provider is not passed.
      Where per-task artifacts and the audit trail go. Relative paths resolve from the repo root.
      Where replay scenarios live, relative to the repo root.
      Disposable workspace where the agent runs. Leave blank to use the system tempdir.
      Where the clean reapply happens. Leave blank to use the system tempdir.

      Loop policy

      Caps on how hard the loop will try before stopping.

      iterations
      How many "modify code, re-validate" rounds before declaring stop. Typical: 3–8.
      attempts
      How many times to retry validation within a single iteration (e.g. flaky-test reruns).
      rounds
      How many diagnostic-fetch rounds before the loop is forced to make a code decision.
      minutes
      Hard budget for the whole loop. The orchestrator stops once exceeded.

      Notes (optional)

      Round-trip back to the form with the "Form" tab above. Comments and uncommented overrides are both preserved.
